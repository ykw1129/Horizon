# GitHub 热门项目栏目设计

## 目标

在 Horizon 每日中文日报中新增独立的 GitHub 热门项目栏目，展示过去 24 小时新增 Star 排名前 20 的项目。每个项目提供简洁中文用途说明，同时保留项目名称、涨星数、主要语言和仓库链接。

## 已确认的用户规则

- 热度口径：过去 24 小时新增 Star，而非历史累计 Star。
- 范围：所有主要语言，不限制编程语言或项目主题。
- 数量：最多 20 个，按新增 Star 从高到低排序。
- 不设最低涨星数；如果榜单不足 20 个，就展示实际取得的项目。
- 描述：中文说明项目用途和适用对象。内容只根据 OSS Insight 返回的仓库描述及统计信息；资料不足时明确说明，不能推测未提供的功能。

## 方案

启用 Horizon 已有的 OSS Insight 趋势源。它从公开 API 获取 GitHub WatchEvents 的新增 Star 排名，不需要 API Key。请求使用 `past_24_hours` 和 `All` 语言，合并并按新增 Star 排序后最多保留 20 项。为满足“不设最低涨星数”，`min_stars` 设为 0。

新增 `github-trending` 处理 profile，并将 OSS Insight 趋势源明确路由到该 profile。profile 只生成一个中文项目简介 block，不配置 `web_search` 或 `history_search`，避免把未核实的 README 内容补写进简介，也避免为这些项目增加外部背景查询。profile 指令要求保留仓库名，说明项目解决的问题、用途及适用对象；项目名、涨 Star 数、语言和仓库链接由日报渲染器从来源元数据直接显示。语言缺失时显示“未提供”，项目描述不足时简介明确说明信息有限。

该 profile 不设置分数门槛，因此 OSS Insight 返回的前 20 项不会再被普通科技新闻的 7 分门槛过滤；它也关闭主题去重，避免把前 20 个仓库合并掉。日报的 `profile_order` 把此栏目放在常规科技新闻之前；其余来源、筛选规则、邮件接收人和每日 08:00 任务保持现有设置。

Horizon 的筛选和摘要层会按 AI 评分排序，因此仅靠来源排序不能保证邮件中的项目仍按涨 Star 排名。`DailySummarizer` 需要对 `github-trending` 组单独按 `stars_gained` 降序排列，并从来源元数据直接渲染仓库名、涨星数和语言，避免依赖模型准确转述这些字段。OSS Insight 以 `All` 查询时，如果 API 没有返回主要语言，抓取器应保留未知值，不得把查询桶 `All` 当作项目语言。该 profile 关闭主题去重，避免分析评分或相似主题合并改变榜单的前 20 个仓库。

## 文件与数据流

- `profiles/github-trending/`: 新增 `profile.json`、匹配、分析和中文简介规则文件。
- 忽略跟踪的 `data/config.json`: 启用 OSS Insight，设置周期、语言、最多项目数及 profile 路由；注册 profile 的日报顺序与无分数门槛设置。
- `src/scrapers/ossinsight.py`: `All` 查询没有主要语言时保留未知值。
- `src/ai/summarizer.py`: 在摘要视图中保持 GitHub 热门栏目按新增 Star 排序，并直接渲染准确的仓库元数据。
- 每日运行：OSS Insight 拉取并排序 → Horizon 对仓库描述及热度指标进行分析 → 生成中文项目简介 → 写入日报并沿用既有邮件投递流程。

## 失败与边界

- OSS Insight 无法访问或返回空榜单时，按 Horizon 现有来源错误处理继续其他来源；该栏目可能为空。
- API 提供的仓库 description 可能为空或很短。此时中文简介必须指出来源信息有限，不应虚构 README 中不存在于输入内容的用途或能力。
- 该榜单衡量的是短期新增 Star，不代表历史总 Star、项目质量或安全性。
- 项目数上限为 20；实际数量可能更少，受 API 返回和仓库 ID 去重影响。

## 验收标准

1. 本地配置通过 Horizon 配置模型校验，OSS Insight 在每日运行中启用，周期为过去 24 小时、语言为 All、最多 20 项、最低涨星数为 0。
2. Horizon 能发现并加载 `github-trending` profile；热门项目被路由到该 profile，不受 `tech-news` 的 7 分门槛或主题去重影响。
3. 日报以独立栏目展示 GitHub 项目，优先于普通科技新闻，并在栏目内继续按新增 Star 降序排列；每项包含中文用途说明、来源元数据中的涨星数、主要语言和仓库链接。
4. 描述不足时输出信息有限提示，不进行无来源推断；其他栏目和邮件定时任务仍可照常运行。
